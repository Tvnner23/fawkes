## Working rule

Implement only the current phase and its necessary acceptance/integration work.
Do not pull distant roadmap phases forward merely because their extension hooks
exist. Before committing a foundational contract, check it against known future
requirements when a small, non-operational hook now prevents expensive rework
later.

Every phase completion requires a whole-system clean sweep: focused and relevant
security/privacy/authorization/replay/permit tests, affected authenticated
HTTP/E2E acceptance, the full Fawkes regression suite, compilation/static
validation, `git diff --check`, final-diff inspection, and explicit cross-system
contract review. Phase status documentation may declare completion only after
that sweep is green; regressions must be fixed and the sweep repeated.

A Phoenix individual is never replaced by a newer generation. Infrastructure
may be upgraded, repaired, migrated, or replaced; a continuity-bearing backup
may restore only its owning Phoenix as the same exclusive continuation. Do not
clone, fork, re-key, or use lived Phoenix state as a genesis template for a new
Phoenix. Future migration/restoration must preserve one authoritative continuity
lineage with an exclusive fenced handoff. Treat duplicate activation or
divergence as quarantined split-brain evidence, never as two canonical copies or
an automatically mergeable continuation. If continuity cannot be honestly
demonstrated, preserve the existing Phoenix and create a genuinely new Phoenix
only as a distinct life.
